Mental model

Every package is a seam, not a framework: it owns one mechanism completely and takes everything domain-specific as a parameter.

None of these know what a "petition" or an "apm project" is. That is the whole design: the consumer hands over the table schema, the queue names, the field registry, the client, or the machine, and the package supplies the correctness the mechanism needs (atomicity, fail-closed, cache invalidation, injection safety). You get to reuse the hard 20% and keep owning the domain 80%.

Reach for a package the moment its trigger condition shows up in the apm design; do not wait until it hurts.

Dependency map

Eight of nine packages are dependency leaves; only filter-ast reaches for result, and cache-aside/outbox merely share a one-function logger shape, not code.

Legend: ① result · ② adapter-seam · ③ cache-aside · ④ outbox · ⑤ filter-ast · ⑥ fsm-oracle · ⑦ depcruise-rules · ⑧ tsconfig · ⑨ biome-config. Solid red = real import edge. Dashed grey = convention-only similarity (both cache-aside and outbox define an identical (entry) => void logger type independently — no shared package).

1. @minsky-org/result

A tagged union so a function that can fail forces its caller to handle both branches at compile time, instead of trusting a comment.

API surface

Result<T, E>
the union: Ok<T> | Err<E>
signature 
type Ok<T> = { _tag: "Ok"; value: T }
type Err<E> = { _tag: "Err"; error: E }
ok / err
constructors
isOk / isErr
type-narrowing guards

Seam design

Consumer suppliesPackage owns
T (success payload), E (error payload)the discriminant tag, the two narrowing guards

Zero dependencies, zero config. This is the leaf every other typed-error package (filter-ast) stands on.

apm-flavored usage

Petition pattern & trap it prevents

Runtime errors travel as a Result; programmer errors throw. The trap this closes: a caught exception silently swallowed by a generic try/catch that logs and moves on, hiding a data-integrity failure. A Result return type makes "did this succeed" a value the type checker forces you to inspect — you cannot forget the error path the way you can forget a catch clause.

Gotchas from the tests

  • • isOk/isErr are true type guards (result is Ok<T>) — use them for narrowing, not a manual result._tag === "Ok" check, or downstream code won't narrow.
  • • The two tags are strictly disjoint (test: isOk(err(x)) is false) — there is no third state; a pending/loading state needs its own type, not a Result.

2. @minsky-org/adapter-seam

One fail-closed policy for every "real vendor client or in-memory Fake" decision, so a missing API key in production throws instead of silently degrading to a fake that eats writes.

API surface

resolveAdapter<T>(args)
the only export
params object 
{ seam: string; credsPresent: boolean;
  real: () => T; fake: () => T }

Seam design

Consumer suppliesPackage owns
a seam name, a creds-present boolean, a real() factory, a fake() factorythe fail-closed branch: creds present → real; creds absent + prod → throw; creds absent + dev/test → warn once, use fake

apm-flavored usage

Petition pattern & trap it prevents

Fail-closed, not fail-open. The petition-management repo routes storage, STT, search, and social-import through this exact seam (per its stack law). The trap: a hand-rolled key ? real : fake ternary evaluated once at import time bakes in whatever env state existed at boot, and in prod a missing key silently degrades to an in-memory fake that discards every write with no error — a P0 data-loss bug that looks like nothing happened.

Gotchas from the tests

  • • The warn is deduped per seam name, module-lifetime (a Set), so calling the same seam twice warns once — two different seam names each get their own warning.
  • • Production check reads process.env.NODE_ENV === "production" directly at call time, so resolving lazily (not at module load) matters if env vars are injected after import.

3. @minsky-org/cache-aside

Read-through caching over ioredis where every cached entry is schema-checked on the way out, so a stale or poisoned shape self-heals as a cache miss instead of crashing or lying to a caller.

API surface

createCache(options)
factory: { withCache, invalidatePrefix }
options 
{ client: CacheClient; logger?: CacheLogger;
  slowGetMs?: number; scanCount?: number }
defineCacheNode / bindRegistry
from /registry: typed key+ttl+schema builders
CacheLogger
from /logger: (entry) => void, defaults silent

Seam design

Consumer suppliesPackage owns
an ioredis-shaped client, a key namespace (db:project:${id} etc), a valibot schema per node, TTL policyread-through fill, schema validation on read (poisoned entry = miss), SCAN+UNLINK prefix purge, in-flight request coalescing, slow-GET detection

apm-flavored usage

Petition pattern & trap it prevents

The writer invalidates — never rely on TTL to fix a stale read. This package holds no key namespace of its own on purpose: the trap it closes is a cache layer that "owns" its own keys and expects every write path across the codebase to know how to reach in and bust them by convention. Instead the write path calls invalidatePrefix explicitly, right where the source of truth changed, making staleness a compile-adjacent responsibility instead of a hope.

Gotchas from the tests / source comments

  • • A Redis read or write failure is logged and swallowed — only the fetcher's own throw reaches the caller. The cache can never be why a page 500s.
  • • In-flight coalescing (the Map of pending promises) is process-local only. A multi-replica deploy still gets a stampede on a cold key across replicas; that needs a Redis SET NX lock, which this package deliberately does not provide.
  • • A cache entry that fails its schema is treated as a miss and silently refetched — useful for a schema migration, dangerous if you expect a hard error on drift.

4. @minsky-org/outbox

Transactional outbox + BullMQ relay so a business write and the async side effect it triggers commit together or not at all, and a job payload is a pointer to re-read, never a snapshot that can go stale.

Data flow

business txn: UPDATE orders SET status='paid' + stageJobs(tx, table, "order.receipt", [{orderId}])
        │  (same transaction — both commit or neither does)
        ▼
outbox_jobs row: status=pending
        │
        ▼  relay poll loop (setInterval)
drainOutbox(): FOR UPDATE SKIP LOCKED claim → status=processing
        │
        ▼
registry.enqueue(job) → BullMQ Queue.add(jobId = outbox row id)
        │                                        (dedupes a re-dispatched stale row)
   ┌────┴────┐
 success    throw
   │           │
 completed   pending (requeue) or failed (attempts exhausted)
        │
        ▼
worker: startWorkers({ handlers }) → BullMQ Worker → defineJob-wrapped handler
        │  parse (valibot) → load (re-read source of truth) → guard → act
   ┌────┴──────────┐
 UnrecoverableError   plain throw
 (bad payload/missing row/    (transient — BullMQ retries
  guard refused) → dead-letter  per its own attempts budget)

API surface (7 subpath exports)

stageJobs
root export: insert N rows for a queue, inside the caller's own tx
OutboxTable
from /table: the drizzle column contract any table must satisfy
drainOutbox
from /relay: one claim-and-dispatch pass
createQueueRegistry
from /queue: BullMQ Queue wrapper with an enqueue deadline race
startWorkers
from /worker-host: mounts a handler registry as BullMQ Workers
createJobFactory / rowOrThrow / isFinalAttempt
from /define-job: parse→load→guard→act pipeline

Seam design

Consumer suppliesPackage owns
the drizzle table (any table satisfying OutboxTable's columns), the queue name vocabulary, valibot payload schemas, load/guard/act per jobFOR UPDATE SKIP LOCKED claim, crash-recovery via stale-lease reclaim, jobId-as-outbox-id dedupe, poison-vs-transient throw discrimination

apm-flavored usage

Petition pattern & trap it prevents

Payloads are claim-checks ({ entityId }), never snapshots. This is the exact ADR-0037/ADR-0056 pattern from petition-management: search-sync ships only {index, entityId}, and the worker re-reads Postgres as the sole source of truth. The trap: if a job payload snapshots the row's data at stage time, a retry that runs out of order (job A staged first but dispatched after a newer job B) silently overwrites B's fresher state with A's stale copy. Re-reading at dispatch time makes retry-reordering harmless by construction.

Gotchas from the tests / source comments

  • • attempts in ClaimedJob is the value after the claim's increment, so markFailure compares against maxDispatchAttempts without a re-read — do not re-fetch attempts before deciding dead-letter vs requeue.
  • • Relay attempts (maxDispatchAttempts, default 60) and BullMQ worker attempts (attempts, default 5) are separate budgets for two different failure classes: "cannot reach the queue" vs "the handler threw."
  • • createJobFactory's dead-letter-vs-retry split is receipt-backed: BullMQ increments attemptsMade only after the processor settles, so isFinalAttempt is made + 1 >= max, the exact negation of BullMQ's own shouldRetryJob check.
  • • The table.test.ts fixture exists specifically to prove a real drizzle table built from the README DDL satisfies OutboxTable — if your table is missing a column the type check catches it, not a runtime surprise.
  • • Queue producer connections re-emit their own errors and an unlistened EventEmitter 'error' event crashes the process — createQueue always attaches an .on("error") handler; don't bypass createQueueRegistry to hand-roll a Queue.

5. @minsky-org/filter-ast

One validated filter tree that compiles to a drizzle WHERE clause, a Meilisearch filter string, or an in-memory predicate, with a golden test suite proving all three agree on the same inputs.

Data flow / compile targets

Core abstractions

FilterAst / Group / Condition
the tree: a Group has a connective (and/or) and children
FieldRegistry / FieldDef
the consumer-supplied allowlist: type + allowed operators per field
validateAst / assertValidAst
Result-returning vs throwing gate; every compiler calls assert first
toDrizzleWhere / toMeiliFilter / evalAst
the three compilers, one per execution target
isCalendarDate / calendarDateToIndexValue
from /calendar-date: YYYY-MM-DD string ↔ UTC-midnight epoch-ms number

Seam design

Consumer suppliesPackage owns
the FieldRegistry (which fields exist, their type, their legal operators), the drizzle column map, the Meili index namedepth/width/array-length caps (DoS hardening), operator↔value shape checks, the three compilers, the drizzle-orm peer dep is optional — the Meili compiler needs no client at all

apm-flavored usage

Petition pattern & trap it prevents

Authz scope is never in this AST — enforced by a comment at the top of ast.ts, not just convention. The trap: a saved-view or shareable filter URL is inherently attacker-controlled input. If the AST were the single place a query's WHERE clause got built, a hostile client could smuggle a clause that widens visibility (e.g. add an orgId is_any_of [...] condition) into what should be a caller-scoped read. Because the executor always ANDs its own scope clause in after compiling the AST, a hostile filter can only narrow or widen what it asks for within the caller's fixed scope, never escape it.

Gotchas from the tests

  • • golden.test.ts self-skips against real Postgres/Meilisearch when unreachable, but the suite body still runs even when skipped (a documented vitest quirk: describe.skipIf still executes the describe body, which creates indexes/tables) — any setup work inside the describe block must itself be gated on if (meiliReachable), not just the describe.skipIf flag, or it throws before the skip takes effect.
  • • calendar-date is deliberately a different field type from date: date is a finite epoch-ms instant, calendar-date is a bare YYYY-MM-DD string compared lexicographically. Mixing them up breaks ordering silently since both are "just numbers or strings" to a careless caller.
  • • The Meili compiler stores calendar dates as UTC-midnight numbers to keep ranges/sorts timezone-free; the projection writer that populates the Meili index must apply the identical transform, or dates drift by a timezone offset between compiler and index.
  • • MAX_FILTER_DEPTH (5) / MAX_GROUP_CHILDREN (20) / MAX_VALUE_ARRAY_LENGTH (50) exist purely because this AST is built from untrusted URL input — do not raise these for a trusted internal caller without re-deriving why they're there.

6. @minsky-org/fsm-oracle

Ask an xstate machine whether a transition is legal and where it lands, without spawning an actor, so every guard/permission-check/UI-affordance in the codebase asks the lifecycle the same one question.

FSM shape this operates on

API surface

assertTransition(machine, from, event)
returns the next state value, or null if illegal
isLegalTransition(machine, from, event)
boolean wrapper over the same check

Seam design

Consumer suppliesPackage owns
an xstate createMachine(...) definition, the current state value, an event objectthe stateless resolveState + standalone transition call, so no actor is ever spawned just to ask a yes/no question

apm-flavored usage

Petition pattern & trap it prevents

Sound only while the machine has zero self-loops — a legal self-loop reads as a refusal, because null literally means "the state value did not change." This is the ADR-referenced trap in petition-management's stack law: the oracle uses xstate v5's transition() + resolveState() (deliberately not the .transition method, which wants an actorScope, and not getNextSnapshot, which is deprecated). If your apm lifecycle machine ever needs a legal transition that keeps the same state value (e.g. a "SAVE_DRAFT" event that stays in "draft"), this oracle will wrongly report it as illegal — that machine needs a different oracle design, not this one.

Gotchas from the tests

  • • An event the machine never declares for that state also returns null, indistinguishable from "declared but goes nowhere" — both read as "illegal," which is usually what you want but is worth knowing if you need to distinguish "unknown event" from "known but refused."
  • • A REJECT-style edge back to an earlier state (submitted → draft) works fine — only same-state self-loops break the oracle, not cycles across two or more states.

7. @minsky-org/depcruise-rules

The eleven portable dependency-cruiser rules of a domain-oriented modular monolith with hexagonal segments, parameterized entirely by regex, so the architecture is enforced by a linter rather than by code review memory.

The eleven rules, grouped

GroupRulesWhat it stops
Puritydomain-stays-puredomain/ importing drizzle, repo/query/handlers, or the wire
CQRSquery-reads-only, repo-writes-only, model-is-leaf, commands-no-wireread/write sides crossing, orchestration leaking into transport
Boundaryhandlers-are-the-sink, no-foreign-module-handlers, shared-no-modules, no-reach-into-compositiona handler being called by another handler, cross-module reach into a private wire surface, shared/ depending on one module's language
Hygieneno-circular, no-orphansimport cycles, dead files

Seam design

Consumer suppliesPackage owns
srcRoot, buckets regex (the top-level bucket alternation), compositionRoot, transport, handlerMount, entryPoints, plus any extraRules that name domain nounsthe eleven layout-shape rules, all regex-parameterized so they hold for any repo laid out as <bucket>/<segment>/{domain,query,repo,commands,handlers}

apm-flavored usage

Petition pattern & trap it prevents

Domain-bound rules stay with the consumer; this package knows no nouns. The exact same shape as petition-management's ADR-0016 modular monolith, and the trap it closes is authz-not-in-AST's cousin: a handler that reaches directly into a grant/permission table instead of going through the capability-gate layer. Petition's own dep-cruiser config appends exactly that as an extraRules entry (handlers-no-grant-tables) on top of these eleven generic ones — the pattern to copy into apm is "generic layout rules from the package, domain rules appended locally," never forking the base eleven.

Gotchas from the source

  • • tsPreCompilationDeps: true is on by default and matters: without it, import type is invisible to dependency-cruiser, so a type-only import can sneak straight through the query/repo boundary undetected. (petition-management's NOTES.md records this exact flag causing 2 circulars at warn severity when first turned on — expect the same discovery pass in apm.)
  • • Config files load via dynamic import(), so the file must be named .dependency-cruiser.mjs (or .cjs) for ESM resolution to work; a plain .js extension under "type": "module" can misresolve.
  • • no-orphans is severity: "warn", not error — entry points must be explicitly listed in entryPoints or every router root flags as a false positive.

8. @minsky-org/tsconfig

Four JSON configs, no code: one non-negotiable strictness baseline, extended by three thin environment layers, so every new package in apm starts from the same TS strictness instead of a copy-pasted config that quietly drifts.

FileAdds over baseUse for
base.jsonstrict, exactOptionalPropertyTypes, noUncheckedIndexedAccess, noUnusedLocals/Params, verbatimModuleSyntaxnever used alone, always extended
node.jsontypes: ["node"], noEmitservers, workers, CLIs
react.jsonjsx: "react-jsx", DOM libs, noEmitbrowser apps
library.jsondeclaration + declarationMap + sourceMap, src→distpublishable packages (like these nine themselves)

apm-flavored usage

Gotchas (the two flags people try to turn off)

exactOptionalPropertyTypes: { x: undefined } does not satisfy an optional x?: string. Build the object with a conditional spread: ...(cond ? { x } : {}), never assign undefined directly to an optional key.

noUncheckedIndexedAccess: arr[0] and record[key] both type as T | undefined, because at runtime they can be. Narrow at the access site; don't silence with a non-null assertion out of habit.

9. @minsky-org/biome-config

The org's biome rule layer on top of ultracite, distributed as one JSONC file to extends, so lint config is shared instead of re-derived per repo.

RuleSettingWhy

apm-flavored usage

Run ultracite, never raw biome. pnpm exec ultracite check / fix, never npx biome directly — raw biome cannot resolve the ultracite/biome/core extends chain, so it emits false positives (useAwait, noEmptyBlockStatements) while missing the real violations this layer is meant to catch.
